- The user runs their own dev instance (ports 3000 and 7777 are often taken by their processes). Vite dev DOES boot in a worktree (verified 2026-07-29): create `apps/web/.env` (gitignored) with just `VITE_API_URL=http://localhost:7777/api` — that satisfies `apps/web/src/env.ts` — then `preview_start` the `web-3001` launch entry (port 3000 usually occupied). Paraglide `src/paraglide/runtime` is generated by the vite plugin at dev start, so its tsc "Cannot find module" errors are pre-existing noise until dev/build has run. For browser-testing role flows without the real backend, a scratch Node mock serving GET `/api/v1/auth/me` (CORS: allow origin + authorization header) on the port in VITE_API_URL works; seed localStorage `access_token`/`refresh_token` (any `header.payload.sig` base64 JWT with `loginMethod`/`loginCriteria`) + future `token_expiry`.

- The BACKEND does boot in a worktree (verified 2026-07-29): user's real `.env` is at the worktree root (gitignored; DB now at 103.224.93.109:6543 — the old postgres.gremoryyx.com host is dead/ENOTFOUND, useful for simulating outages via an `apps/backend/.env` POSTGRES_HOST override, which `load-env.ts` applies with override:true). Run `pnpm install` first (worktrees share no node_modules). Port 7777 is usually taken by the user's own backend — temporarily add `"autoPort": true` to the `backend` entry in `.claude/launch.json` (revert before committing; it's tracked) and the server binds the harness-assigned PORT (main.ts prefers PORT over BACKEND_PORT). Login endpoint: POST /api/v1/auth/login; admin creds are DEFAULT_ADMIN_EMAIL/PASSWORD in .env.

**Why:** avoids wasting time re-attempting preview_start; the env gap is the user's local setup, not a bug to fix.

**How to apply:** typecheck backend with `npx tsc --noEmit -p apps/backend/tsconfig.json` (ignore pre-existing `src/app/*` NestJS stub errors) and web with a grep-filtered `npx tsc --noEmit` (agency-portal has many pre-existing errors). Regenerate routes with `pnpm --filter innocenz-admin generate-routes`.

- **"Internal server error" on web login + "Cannot reach backend" on mobile = backend not running** (verified 2026-07-30): the backend had crashed on boot with `ERR_MODULE_NOT_FOUND: pdfkit` because `pnpm install` was never run on this device after the 30 Jul PV PDF/Excel work added `pdfkit`/`exceljs` to apps/backend. Diagnose with `netstat -ano | findstr :7777` (empty = dead) + `preview_logs`. On this machine `pnpm install` can fail with `ERR_PNPM_ENOENT ... jest-config_tmp_<pid>\node_modules` (Windows file-lock/AV in Downloads): fix = delete `node_modules\jest-config*` and any `node_modules\*_tmp_*` dirs, re-run `pnpm install --prefer-offline`, then `preview_stop` + `preview_start` the `backend` launch entry. Backend binds all interfaces — health at both `localhost:7777` and the LAN IP (`http://<ipv4>:7777/api/v1/health`) must return 200 for web + phone. PR login stores phone E.164: `POST /auth/login` needs `{"phoneNum":"+60123456789"}` (with `+`); the mobile app normalizes typed `60123456789` itself.

- ECC GateGuard fact-forcing hooks are active: before the first Bash command and the first Edit/Write of EACH file per session, you must present (in the text) importers/callers, affected API, data schemas, and the user's verbatim instruction, then retry the same call. Denials are normal; just restate facts and retry. Related: [[innocenz-plan-change-flow]].
